# Can one source-defined attention ordering become an integer program?

This is one written, unexecuted feasibility cut after the [token-history assay](../token-history-address-program.md). It is not a new support-label learner, general symbolic law or image generator. No implementation or job is queued by cycle 94. Full research/storage review 93 is current, next 96; new evidence may supersede this question.

The selector family omits query-position dependence. Instead of expanding its fitted vocabulary, ask whether the qualified source ordering can be compiled into a reusable finite address program with explicit storage cost.

## One fixed domain

Use head 0, inactive padding query ID 151643, and the 30-token active discovery alphabet already frozen in the cycle-94 discovery receipt. Retain absolute query/key positions in 0..511. For padding queries, legal keys have j<i and an active mask. Key tokens may be any member of that fixed alphabet. No transfer tokens enter the alphabet after outcomes are opened.

First perform a source-only domain/size census. One raw ordinal table has

\[
|V|\sum_{i=0}^{L-1}i=|V|L(L-1)/2
\]

entries. For |V|=30 and L=512 this is 3,924,480 ordinals. The largest row orders 15,330 candidate token/position pairs and fits uint16, giving 7,848,960 raw ordinal bytes before metadata. This is an upper construction size, not a lower bound on a compressed program. General query tokens, all heads, the full vocabulary and later contextual layers have separate costs and no established economical extension.

## Source construction, not a new label fit

For each absolute query clock i, obtain the qualified represented query for padding ID151643 and all qualified key vectors for (b,j), b in the frozen alphabet and j<i. Use the pinned token-local compiled assets and exact source normalization/rotary/BF16 operand policy. Charge every asset read and offline score product. No contextual hidden states or complete-prefix support cache may supply this construction.

Declare a new deterministic, candidate-bank-independent score contract for this feasibility cut: widen the qualified BF16 operands to FP64, divide each by the qualified headDim**.25 scale in FP64, multiply each coordinate pair in FP64 without contraction, then use pinned Python math.fsum over those 128 products. This is offline learned attention arithmetic, fully charged. It is not an assertion of exact parity with the old NumPy keys[:count] @ q reduction. Different candidate-bank sizes/layouts can select different reduction geometry there; represented-operand identity and tiny tests do not establish a context-independent old-reader finite comparator. Retain every measured old-reader ordering difference as a separate observation. Do not promote it into all-history old-reader parity.

Sort candidate pairs by this declared deterministic score, decreasing, then key position, increasing. An additional token-ID tie-break at an identical position is harmless because a valid history has only one token at that position. Serialize uint16 little-endian ordinals by increasing query clock, then sorted token ID, then increasing key position; use gzip level9 with mtime0 as the single fixed compression format. Do not search compression formats or alter the domain after seeing outcomes. The initial source audit must establish exact asset identities, scale and pinned Python/operand numerical profile before numerical execution; ideal relative-phase formulas do not certify the absolute-position BF16 result.

Serving accepts only IDs/masks/clocks and advances its own admitted history. For a supported padding query, gather integer ordinals for admitted token/position pairs and select four in order. Restricting one global order to an arbitrary valid subset preserves its order. This supplies a bounded all-history argument only for the newly declared context-independent deterministic score contract. Equivalence with every finite old-reader history remains unestablished. This stores local candidate order, not a table indexed by complete prompts or prefixes.

Unknown admitted key tokens make the queried history unsupported; do not drop them or assume their score is small. A query with a different token ID, an active query mask or an out-of-range position is unsupported. Retain unsupported rows and coverage. No Q/K vectors, scores, weights, dot products or fitted sinusoidal coefficient evaluation enter serving.

## What the result would decide

Measure source compilation, score/sort work, raw and fixed-compressed bytes, decompression/residency, exact integer serving, comparisons, history growth and supported coverage. Use fresh serving and mechanics controls, preserving all old failed/adverse results. Source numerical identity and valid order restriction are integrity requirements; economy and coverage are observations, not discovery stop gates. The researcher may end this bounded feasibility question after an adverse size census without launching a tensor job or automatic expansion.

A successful construction would supply one source-derived ordering under the declared deterministic finite contract within a small alphabet, for one head/query type. Exact integer serving under that contract and measured differences from the old finite reader remain distinct. It would not produce logits, soft weights, values, the other heads/query types, later contextual state, denoising or pixels. Subsequent native-consumer evidence would be required for a new image claim. The arbitrary-prompt zero-neural goal remains active and unsolved.
