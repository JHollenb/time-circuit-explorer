# A standalone relative-mass producer for the first read

Status: design question after the [cycle 97 read effect account](../first-read-route-payload.md). No implementation, fit, score-table expansion, model job or native image is queued. Before any execution, compare existing attention/source-order/lexical work and the current research survey; use an equivalent existing result rather than repeat it.

The one-token crossover now has an inexpensive conditional description. Common unedited selected addresses retain their relative weights, and the new edited-address mass plus an already-paid common value mixture determines the update. Both the mass and mixture are still supplied in that account. The next useful boundary is a standalone read's complete weights from input, without an old prompt's weights or one supplied scalar b.

For selected addresses j₀,…,j₃, choose an input-defined reference j₀ and write

\[
g_i=s(j_i)-s(j_0),\qquad g_0=0,\qquad p(j_i)=\frac{\exp(g_i)}{\sum_{k=0}^3\exp(g_k)}.
\]

The three relative gaps remove an irrelevant common score offset. Ordering determines gap signs/order but not their magnitudes: positive rescaling preserves ranks while changing these weights. This elementary ambiguity already explains why the exact rank program cannot by itself specify the weighted read. It is not a proof that a cheap gap producer is impossible.

Ask whether an input-defined program of ordered token IDs, masks and absolute positions can produce those gaps or equivalent positive masses for the same padding query/head and stated token domain. Serving must exclude Q/K dot products, original model projections, a per-history weight table, supplied b, supplied old conditional weights and native states. Any token/position compilation, reduced arithmetic or learned source asset must be named, sized and charged; simply evaluating the original learned arithmetic in another library does not meet the objective.

The first step is mathematical and source/cost feasibility. Compare an analytic positional law, discrete arithmetic recurrence and bounded compiled source function; do not begin a coefficient/precision search or silently widen the current 30-ID domain. State the proposed finite arithmetic contract and its difference from the historical selected reader. Estimate compilation products, runtime work, persistent state, resident asset bytes and coverage. A table that only re-expresses paid scores may be useful engineering while leaving the explanatory or economy question unresolved.

If a concrete candidate survives that design comparison, write one smallest matched transaction before execution. Preserve signed weight/read errors, every dependent row and counterexample; do not use an arbitrary quality threshold to suppress the effect account. Unknown IDs or inapplicable histories must be explicit. Current-query selected supports may be declared inputs for this bounded producer question, but that does not provide end-to-end source-independent routing. The common value mixture and complete values must also be formed and charged before calling the result a standalone read.

This is still one first-layer component. Native output projection, residual/MLP/contextual continuation and pixels remain separate missing computations. Full research/storage review 96 is current, next 99; a material new result should trigger earlier advisor review. No automatic native assay or image follows this design question.
